2 · Main classifier

classify_vault.py

Walks the vault, applies rules then LM-Studio fallback, writes R2 frontmatter to confident notes, drops uncertain ones into a review queue.

Signature scripts/classify/classify_vault.py

Notes scoring ≥ 0.80 get frontmatter written in place. Notes < 0.80 go to classification-review.md (and .html with --html) for manual review. Progress bar + .classify_progress.json heartbeat make long runs (AWS: ~15 h) safe to monitor from a separate terminal.

Flags

--vault PATHRequired. Obsidian vault root (e.g. ~/Documents/ObsidianVault/Personal).
--folder NAMERestrict to one subfolder. Default: scan the whole vault. Skip-list (wiki/, Personal-backup-*, hidden dirs) still applies.
--limit NStop after processing N unclassified notes. Default: no limit. Already-classified notes are not counted toward the limit.
--htmlAlso write classification-review.html alongside the .md. Self-contained, opens in any browser, links into Obsidian via obsidian:// URLs.
--dry-runCount what would happen; no frontmatter writes, no checkpoint, no heartbeat. Review queue printed to stdout instead of file.

Common patterns

Pilot — small folder, foreground, watch the bar live:

scripts/classify/venv/bin/python scripts/classify/classify_vault.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Job Hunt"

AWS scale-out, chunked, with HTML review output:

scripts/classify/venv/bin/python scripts/classify/classify_vault.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Evernote/notes/AWS" --limit 2000 --html

Dry run — counts only, no writes:

scripts/classify/venv/bin/python scripts/classify/classify_vault.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Job Hunt" --dry-run

Background overnight, log to file, monitor from another terminal:

nohup scripts/classify/venv/bin/python scripts/classify/classify_vault.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Evernote/notes/AWS" --limit 4000 --html \
  > /tmp/classify-aws.log 2>&1 &

tail -f /tmp/classify-aws.log
cat ~/Documents/ObsidianVault/Personal/.classify_progress.json
3 · Post-run audit

sample_classified.py

Pull N random auto-classified notes and inspect them. The decision gate between "ship it" and "stop and investigate" after every chunk.

Signature scripts/classify/sample_classified.py

Skips review-queue notes (those don't have full R2 frontmatter yet). Reuses the shared skip-list from classify_vault, so wiki/ and Personal-backup-* are never sampled.

Flags

--vault PATHRequired. Obsidian vault root.
--folder NAMERestrict sampling to a single subfolder (default: whole vault).
--n NNumber of notes to sample. Default 10. If fewer matched, all matched are returned.
--filter F=Vfield=value filter; repeat for AND-combine. Example: --filter type=meeting --filter org=Amazon. OR/NOT not supported in v1.
--seed NRandom seed for reproducible sampling. Use a fresh value each session to see different notes.
--html PATHWrite the sample as a self-contained HTML file at PATH (with obsidian:// click-through). Suppresses terminal output. Suggested: ~/Documents/ObsidianVault/Personal/sample_classified.html.

Common patterns

Spot-check the latest AWS chunk in HTML:

scripts/classify/venv/bin/python scripts/classify/sample_classified.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Evernote/notes/AWS" --n 20 --seed 7 \
  --html ~/Documents/ObsidianVault/Personal/sample_classified.html
open ~/Documents/ObsidianVault/Personal/sample_classified.html

Only Amazon meetings, reproducible across runs:

scripts/classify/venv/bin/python scripts/classify/sample_classified.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --filter type=meeting --filter org=Amazon --seed 42

Capture a large sample to file for offline review:

scripts/classify/venv/bin/python scripts/classify/sample_classified.py \
  --vault ~/Documents/ObsidianVault/Personal --n 50 > samples.txt
4 · One-shot data hygiene

fix_evernote_titles.py

Quotes unquoted title: values in Evernote-export YAML frontmatter so yaml.safe_load can parse them. Run once per Evernote import folder before classifying.

Signature scripts/classify/fix_evernote_titles.py

Evernote exports write titles raw — values like 1-1: Stefan, - Business Card, or * [[link]] break YAML parsing. This script wraps each title in single quotes (with apostrophe-doubling per YAML spec). Round-trip preserves the original string verbatim. Idempotent — re-running on already-quoted titles is a no-op.

Flags

--vault PATHRequired. Obsidian vault root.
--folder NAMERestrict to one subfolder (default: whole vault).
--limit NStop after N successful fixes (useful for spot-checking).
--dry-runShow what would happen; no writes.

Common patterns

Dry-run on AWS subset first:

scripts/classify/venv/bin/python scripts/classify/fix_evernote_titles.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Evernote/notes/AWS" --dry-run

Apply for real:

scripts/classify/venv/bin/python scripts/classify/fix_evernote_titles.py \
  --vault ~/Documents/ObsidianVault/Personal \
  --folder "Evernote/notes/AWS"
5 · After classification is done

migrate_vault.py

Moves classified Evernote-imported notes out of Personal/Evernote/ subfolders to the right vault root. End state: zero Evernote/ subfolders.

Signature scripts/classify/migrate_vault.py

Routes by context frontmatter: work → Business vault, personal or education → Personal vault root. Unclassified notes are skipped with a warning — run classify_vault first. Filename collisions get _2, _3 suffixes — nothing is ever overwritten. Migration log appended to ~/Documents/ObsidianVault/Business/migration-log.md.

Flags

--personal PATHRequired. Personal vault root (source).
--business PATHRequired. Business vault root (destination for work notes).
--confirmApply moves. Default is a count-only dry run.
--dry-runForce dry run even if --confirm is also passed. Wins on conflict — safety net for accidental --confirm.
--limit NCap the number of notes moved this run (default: no cap). Useful for staged rollout.

Common patterns

Preview only — counts, no moves (default):

scripts/classify/venv/bin/python scripts/classify/migrate_vault.py \
  --personal ~/Documents/ObsidianVault/Personal \
  --business ~/Documents/ObsidianVault/Business

Staged rollout — first 100 only:

scripts/classify/venv/bin/python scripts/classify/migrate_vault.py \
  --personal ~/Documents/ObsidianVault/Personal \
  --business ~/Documents/ObsidianVault/Business \
  --confirm --limit 100

Apply the rest after spot-checking the first 100:

scripts/classify/venv/bin/python scripts/classify/migrate_vault.py \
  --personal ~/Documents/ObsidianVault/Personal \
  --business ~/Documents/ObsidianVault/Business --confirm
6 · Reading the live status

Progress bar field reference

A single line, dense with signal. Each field is a different question the bar is answering simultaneously. This is what a healthy AWS chunk looks like a few minutes in:

Classifying:  15%|██▏ | 298/2000 [09:54<52:14, 1.85s/note, auto:212 | review:86 | skip:1240 | missing:0 | ac:71% | rules:14% | lm-avg:7.8s | overall: 989/6375 (15.5%) | corpus-eta:3.4h]

The bar itself 15% | ██▏ |

Progress through the current chunk. Denominator is min(unclassified-in-folder, --limit). Already-classified skips don't advance the bar.

HealthyClimbs steadily. If stuck at the same % for >2 min, LM Studio probably hung — check it loaded the model.

Counter 298/2000

Classification attempts so far, out of the chunk target. Always auto + review, never includes skipped or missing.

HealthyIncrements on every attempt — about once per lm-avg seconds.

Time [09:54<52:14, 1.85s/note]

Elapsed-since-start < remaining-in-chunk, then per-note rate. The rate fluctuates as the rules/LM mix shifts.

HealthyRate trends downward as the per-note average smooths out. s/note > 30 sustained = LM degrading.

auto:N — auto-classified this run

Confident classifications (≥ 0.80) that got R2 frontmatter written in place. The number that actually made progress.

HealthyClimbs steadily. Should be the dominant counter on AWS (target ~70% of attempts).

review:N — review queue this run

Notes where both rules and LM came back < 0.80, or where the body was too short to classify. Land in classification-review.md/html for you to triage.

Healthy~20–30% of attempts on AWS. If it dominates over auto, your keyword dicts may not cover the folder's content.

skip:N — already classified

Notes the walker found but skipped because they already have up: frontmatter. Jumps in bursts when the iterator hits a run of previously-classified files.

HealthyGrows mostly at the start of a chunked run, then plateaus. Big numbers here are normal across chunked runs.

missing:N — vanished during the run

Files the directory walk found at startup but couldn't read by their turn — usually because you deleted or renamed them mid-batch while triaging the review queue. Silently skipped.

Healthy0 unless you're triaging in parallel. Any non-zero value is the FileNotFoundError patch absorbing your concurrent edits — no action needed.

ac:X% — auto-classify rate

Of all attempts this run, what % were confident enough to auto-classify. Formula: auto / (auto + review) × 100.

Healthy65–85% on AWS once the chunk is warmed up. < 50% sustained = investigate why the LM is uncertain so often.

rules:X% — rules-only catch rate

Of the auto-classified notes, what % were caught by the rules cascade alone (no LM call). Higher = cheaper, no LM tokens spent.

Healthy5–20% on AWS. Job Hunt was 0%. Climbs as you add new _TITLE_TYPE_RULES patterns based on review-queue feedback.

lm-avg:Xs — LM latency

Running average of LM Studio response time across all calls this run. lm-avg:- means no LM calls yet (everything was rules-caught or short-body).

Healthy4–12s on Gemma 4 E4B with GPU offload. > 60s sustained means GPU offload disabled or another process is hogging the GPU.

overall: X/Y (Z.Z%)

Corpus-wide classification progress across all chunked runs, NOT just this chunk. Calculated as corpus_classified_at_start + auto_this_run.

HealthyClimbs slowly across an evening of chunked runs. Hits 100% when the whole folder is classified.

corpus-eta:Xh

Projected wall-clock hours to classify the remaining unclassified corpus, extrapolated from this run's observed rate.

HealthyDecreases monotonically as you make progress. Big swings early in the chunk are normal until the rate stabilises.
Same fields appear in ~/Documents/ObsidianVault/Personal/.classify_progress.json under the totals key — useful for tailing run state from a second terminal or a script.
7 · After each chunk

Reviewing the output

Five things land alongside the vault when a chunk finishes. Look at them in this order.

classification-review.html · in-browser triage

Self-contained HTML report of every note in the review queue, with proposed type/org, confidence, reason, and an obsidian:// click-through link to open the note. Generated when you pass --html on classify_vault.py.

  • Open from Finder or with open ~/Documents/ObsidianVault/Personal/classification-review.html
  • For each row: open the note in Obsidian, decide whether to delete, edit frontmatter manually, or leave for next pass
  • The file is overwritten on every classifier run — archive it manually with a timestamped suffix if you want to preserve a prior queue

classification-review.md · same content, Markdown

Pipe-delimited table of the review queue. Useful if you'd rather triage inside Obsidian itself (the file is in the vault) or process with shell tools.

| Note | Proposed type | Proposed org | Confidence | Reason |
|------|---------------|--------------|------------|--------|
| [[Some Note]] | technical | Amazon | 0.65 | low confidence from both classifiers |

sample_classified.html · post-run sanity check

Run after each chunk to spot-check N random auto-classified notes. The decision gate between "ship it" and "stop and investigate".

  • Each row: title, frontmatter (type/org/context/confidence), people, tags, body excerpt, obsidian:// link
  • Pick a fresh --seed per check to see different notes
  • Decision rule: if < 60% look right by eye, stop and tune rules/keywords before the next chunk

.classify_progress.json · heartbeat

Atomic-written snapshot of the run's totals. Updates every checkpoint_interval notes (default 50). complete: true after a clean exit; complete: false if the process was killed.

{
  "started_at": "2026-05-14T19:29:30+10:00",
  "last_updated": "2026-05-14T20:32:38+10:00",
  "complete": true,
  "vault": "/Users/.../ObsidianVault/Personal",
  "folder": "Evernote/notes/AWS",
  "totals": {
    "scanned": 827,
    "auto_classified": 364,
    "needs_review": 136,
    "skipped_already_classified": 327,
    "skipped_missing": 0,
    "lm_calls": 450,
    "lm_call_avg_seconds": 8.4
  }
}

.classify_checkpoint.json · processed-paths list

JSON array of every path the run touched. Survives kills so resuming from where you left off works correctly — is_classified() on the next run sees the frontmatter that was already written. Safe to ignore most of the time.

8 · While triaging the review queue

Triage type & org reference

When you click Reclassify… on a card, the prompts ask for a type and an org. These are the canonical values the classifier understands — anything outside the whitelist is rejected. Pick by content, not by folder (lots of personal notes will sit in Evernote/notes/AWS/ because that was your default Evernote notebook for 13 years).

Three decisions per row: Delete (junk / duplicate / clipping residue), Reclassify (valuable but mis-typed), or Skip (do nothing — leave it for a second look). Auto-prune drops rows you've already actioned on the next refresh.

Type values (15)

TypeRoutes to MOCUse for
meeting[[Meetings]]Real meeting notes, standups, 1-1s, sync notes
technical[[Technical]]AWS architecture, design docs, RFCs, deep-dives
reference[[Reference]]Cheatsheets, summit / conference notes, summaries, third-party clippings
interview[[Interview Prep]]Interview prep, STAR stories, behavioural answers
management[[Leadership]]OLR / PIP, calibration, performance reviews, team-health docs
application[[Job Hunt]]Job applications, recruiter chats, role research
career[[Career]]CV, career timeline, achievements summary
pattern[[Patterns]]Architecture patterns (CQRS, saga, hexagonal, etc.)
personal[[Personal]]Anything personal-life: travel, hobbies, photos with context, journal
note[[Personal]]Catch-all — only use when nothing else fits. Try to avoid.

9 · When to stop and tune

Decision gates between chunks

Three signals that mean "stop the run, don't just keep chunking". If you ignore them and barrel on, you'll create review-queue debt or miscategorised notes you'll regret later.

Sample < 60% correct. Run sample_classified.py --n 20 after every chunk. If fewer than 12 / 20 look right by eye, the rules dicts or LM prompt aren't matching this folder's content. Investigate which type/org is over-firing before the next chunk.
Review queue exceeds 40% of the chunk. The pipeline is punting too often. Inspect classification-review.html — if a clear pattern shows up (e.g. "20 short Evernote notes all need type: note"), add the keyword cluster to rules_classifier.py's _TITLE_TYPE_RULES and re-run. Compounds well: each rule lifts every future chunk.
LM-avg climbing past 60 s and staying there. LM Studio is either CPU-only (GPU offload disabled) or another process is taking the GPU. Open LM Studio Local Server → max the GPU-offload slider → reload model. Then re-run.
