Test in Obsidian · 3-minute smoke procedure

How to verify the MOC inbox pattern

This is the single most important manual check. If this works, the whole Dataview-based scheme is wired correctly. If it doesn't, all the downstream classification work is producing data that won't surface in the MOCs.

A

Open the Personal vault in Obsidian

Make sure Dataview plugin v0.5+ is enabled. Open Meetings.md at the vault root — you should see "Inbox" and "Organised" sections.

B

Create a throwaway test note

New note in the vault root called _moc-smoke-test.md with this content:

---
title: "MOC smoke test"
type: meeting
org: Personal
context: work
up: "[[Meetings]]"
---

Throwaway content to test the Dataview inbox query.
C

Re-open Meetings.md

Expected: _moc-smoke-test appears in the Inbox list within ~2 seconds (Dataview's default refresh interval). If it doesn't appear within 5 s, try Command-R to force a refresh.

If still missing: check the .md file's frontmatter parses (the up: value must be quoted because [[ starts a YAML flow sequence). Check Dataview's settings → "Use as default" → "YAML inline fields" is enabled.

D

Add the test note to Organised, watch it leave Inbox

Edit Meetings.md, paste - [[_moc-smoke-test]] under the ## Organised heading. Save. The note should disappear from the Inbox list on next render. That proves the !outgoing([[]]) exclusion is working.

E

Delete the test note and repeat for the new MOCs

Repeat the smoke test for Job Hunt.md, Interview Prep.md, and Leadership.md (Business). These are the new MOCs that didn't exist before — verify each one before relying on them.

F

Verify the legacy rewrite stuck

Open any note in Personal/Meetings/ (e.g. 2026-03-19 - Heart Rate Zones.md). The frontmatter should show up: "[[Meetings]]" — not the old "[[Meetings Homepage]]". Eight notes were rewritten on 2026-05-14.

In Obsidian's graph view, those notes should appear as spokes around the new Meetings hub.
